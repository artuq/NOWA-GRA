### History of this run (important context)

The first full-suite run reported **9 failures**. Root-cause analysis split them into two groups:

**Group 1 — 3 false failures from save-file pollution.** The test process boots the real Autoload chain, and `SaveSystem._ready()` restores `user://save.json` — the developer's live playtest save (Cringe clamped at 100, milestones set, active path at Tier 2) leaked into test assertions. Moving the save aside eliminated these 3. **Systemic finding**: tests are not isolated from the real user save — logged as follow-up (see below).

**Group 2 — 3 genuinely failing tests, all STALE (pre-Sprint-8).** Verified via `git stash` that they fail on the pre-sprint tree too. All were assertions left behind by deliberate behavior changes:
- `action_grid_unlock_test.gd` + `action_grid_interaction_test.gd` — asserted `disabled == true` for locked slots; Story 005 (Sprint 7, locked slot preview) deliberately made locked slots enabled-but-grayed for tap→toast. **Fixed**: locked-state predicate rewritten to icon `LOCKED_MODULATE` + "🔒" title prefix; 3 tests updated to the preview contract (real action icon, unlock-requirement stats text, all buttons re-enabled after action).
- `card_swipe_gesture_test.gd` — gdUnit's `simulate_screen_touch_*` window-to-viewport coordinate scaling inflated drag deltas ~2.5× in the headless harness (720×1280 viewport, `canvas_items` stretch). **Fixed**: all 7 tests rewritten to inject synthetic `InputEventScreenTouch`/`Drag` directly into `CardScreen._input()` — deterministic, viewport-space, velocity 0 (removed the old "settle drag" flick workaround).

**Additional finding**: gdUnit4 aborts a suite on first test failure — earlier runs reporting "337 test cases" were truncated. The true suite size is 360, all passing after fixes.
