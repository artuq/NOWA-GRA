- **2026-06-23 — ROADMAP/DECISION FLAG (not debt yet)** (Platform / Rendering): If CrazyGames (web/HTML5) becomes a release target, it forces an architecture decision currently unmade. Godot 4 web export requires the **Compatibility (GL Compatibility) renderer** — Forward+/Mobile do not run in-browser. `technical-preferences.md` currently specifies Forward+/mobile for Android. Compatibility runs on Android too, so the clean move is to standardize on Compatibility for web+mobile (our 2D game needs nothing more). Also needed for CrazyGames: `crazysdk-godot-4` addon (Full Launch only), Brotli/Gzip-compressed production builds, COOP/COEP threading verification, and a check that ADR-0002 (atomic save) + Offline Progress behave under web's `user://`→IndexedDB mapping. NONE of this blocks current backend work (pure GDScript, renderer-agnostic). Decide + write an ADR when the rendering/UI layer is reached, not before (YAGNI). Verified feasible 2026-06-23 (CrazyGames officially supports Godot 4: docs.crazygames.com/sdk/intro).

- **2026-06-23** (Core Resource Mutation & Clamping — real bug, not advisory, already fixed): `tests/unit/resource_system/core_mutation_test.gd` passed bare `{}` dictionary literals directly to `apply_delta(deltas: Dictionary[StringName, float])`. Godot 4.4+'s typed-dictionary parameter matching against inline literals is inconsistent/non-deterministic in this Godot version (4.6.2) — some calls were accepted, others rejected with "element type" mismatch, depending on context, not on the literal's shape. Fixed by declaring an explicitly-typed local `Dictionary[StringName, float]` variable before every `apply_delta()` call site. Production code's typed signature is correct and unchanged. — tracked from `production/epics/resource-system/story-003-morale-drain-rate.md`
- **2026-06-23** (Core Resource Mutation & Clamping — real bug, not advisory, already fixed): `core_mutation_test.gd`'s `after_test()` called `_rm.queue_free()` unconditionally, but GdUnit4's own GC (`GdUnitMemoryObserver`) can free tree-added nodes between test stages when a test uses `await` (e.g. `assert_signal`), causing a double-free crash. Fixed with an `is_instance_valid(_rm)` guard before `queue_free()`. — tracked from `production/epics/resource-system/story-003-morale-drain-rate.md`
