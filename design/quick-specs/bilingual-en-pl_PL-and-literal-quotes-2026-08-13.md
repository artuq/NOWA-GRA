# Quick Design Spec: Bilingual `en` / `pl_PL` Copy and Literal Quotes

**Type:** Addition

**Systems:** Localization / Card Content / UI Copy

**Date:** 2026-08-13

**Source locale:** `en`

**Added locale:** `pl_PL`

## Change Summary

King of Cringe gains a Polish presentation layer while preserving one gameplay
contract across both locales. Polish copy may contain culturally specific,
literal quotations, but only after the exact text and intended use pass the
clearance gate. Locale selection changes player-facing copy and formatting only.

## Non-Negotiable Contract

1. **Mechanics are identical in `en` and `pl_PL`.** Locale does not branch card
   eligibility, option order, effects, rewards, counters, milestones, weights,
   cooldowns, minigame scoring, progression, saves, RNG, or achievements.
2. **IDs are locale-independent and stable.** `card_id`, `option_id`, resource
   IDs, milestone IDs, challenge IDs, and save keys never contain translated
   labels and never change when the language changes.
3. **Resolution routes by `option_id`, never by visible text or array label.** A
   translator may change the display label without changing what the option
   does. The same `option_id` resolves the same effects in both locales.
4. **English is the fallback.** Missing or invalid `pl_PL` copy resolves through
   `pl_PL -> en`. A release build never presents a raw localization key.
5. **Quotes are literal and gated.** A quote is used exactly as cleared, with no
   paraphrase, censorship, correction, shortening, extension, or translation.
   Only registry entries cleared for the exact locale and scope may ship.
6. **A locale-specific quotation never controls gameplay.** The English and
   Polish strings may deliver culturally adapted punchlines, but they occupy the
   same string key and attach to the same mechanic/option outcome.
7. **Marketing clearance is separate.** Permission for `in_game_text` does not
   allow use in Google Play copy, screenshots, trailers, notification text,
   voice-over, or other media.
8. **Cultural adaptation is not literal translation.** A Polish quotation and
   its English string share a gameplay key and outcome, but the English copy is
   independently authored for its own rhythm and context. Neither locale is
   generated by translating the other quotation word for word.

## Data Contract

Gameplay data references localization keys rather than embedding player-facing
copy. Recommended key pattern:

```text
cards.<card_id>.body
cards.<card_id>.options.<option_id>.label
cards.<card_id>.options.<option_id>.reaction
actions.<action_id>.label
ui.<screen>.<element>
```

Example of the invariant boundary:

```yaml
card_id: sponsor_offer_shady
options:
  - option_id: accept
    label_key: cards.sponsor_offer_shady.options.accept.label
    reaction_key: cards.sponsor_offer_shady.options.accept.reaction
    resource_deltas: { Reach: 160, Cringe: 22, Morale: -8, Sponsors: 3 }
  - option_id: decline
    label_key: cards.sponsor_offer_shady.options.decline.label
    reaction_key: cards.sponsor_offer_shady.options.decline.reaction
    resource_deltas: { Reach: 90, Cringe: -5, Morale: 5, Sponsors: 0 }
```

`resource_deltas` and all other mechanics exist once, outside locale files.
Locale tables contain only display strings and translator context.

Every translatable entry must carry or link to:

- screen and gameplay context;
- speaker/voice where relevant;
- placeholders and their meaning;
- preferred and review character limits;
- tone note;
- screenshot reference when ambiguity remains; and
- quote registry ID when the string is controlled literal material.

## Locale and Fallback Rules

- Canonical locale IDs are `en` and `pl_PL`.
- `en` is complete and is the runtime fallback for `pl_PL`.
- The player's locale preference may be changed at runtime and persisted, but
  it must not alter the run state beyond that preference.
- If a `pl_PL` key is absent, empty, malformed, or fails placeholder validation,
  use its `en` value and log a development diagnostic.
- If the English fallback is also missing, development builds may show an
  explicit missing-string marker; release validation blocks the build.
- Parameter values are formatted for the selected locale at presentation time.
  Stored numeric values remain locale-neutral.

## Literal Quote Pipeline

1. A proposed quote is recorded as `candidate` in
   `production/localization/literal-quote-clearance-registry.md` with exact text,
   declared source, desired context, and desired scopes.
2. Source and wording are verified against an authoritative reference.
3. Rights/legal review records its evidence, permitted wording, attribution,
   territory, platforms, duration, languages, and media scopes.
4. Only an authorized reviewer may set `clearance_status: cleared` and
   `shipping_status: allowed`.
5. The approved text is copied verbatim into `pl_PL`; it is not retyped from
   memory and is normalized to Unicode NFC.
6. Automated/content QA compares the locale value with the registry text.
7. If clearance is missing, rejected, expired, or narrower than the planned
   use, ship ordinary original/localized copy under the same key instead.

## UI and Font Requirements

- Existing responsive containers must be tested with Polish strings and
  diacritics: `ą ć ę ł ń ó ś ź ż` and uppercase equivalents.
- The production font must cover Latin Extended characters without glyph
  substitution inconsistent with the pixel-art style.
- Options must remain readable before commitment; no locale may hide or reorder
  an option.
- Text fitting uses wrapping or container growth before aggressive font
  reduction. Truncation must never change a choice's intent.
- Automatic line wrapping may visually split a literal quote but may not change
  its text.

## Save and Migration Rules

- Existing saves default to `en` only when no locale preference exists; first
  launch may otherwise use the supported device locale according to the final
  settings/onboarding policy.
- Save history records stable IDs, not localized labels.
- Switching between `en` and `pl_PL` mid-run produces no resource or progression
  mutation.
- Older save data must not be migrated by matching translated text.

## Acceptance Criteria

- [ ] Given the same starting save and deterministic inputs, `en` and `pl_PL`
      produce identical mechanical state after every action and card choice.
- [ ] Every card option has a stable, non-localized `option_id`.
- [ ] Changing a translated option label cannot change its resolution route.
- [ ] A missing valid Polish string displays the English fallback, not a raw key.
- [ ] Switching locale during a run changes copy only and preserves all gameplay
      state.
- [ ] Every literal-quote option declares `cultural_reference_locale: pl_PL`
      and a registry id; its English catalog entry remains original English
      copy and never duplicates the Polish quotation.
- [ ] Placeholder names and counts match between `en` and `pl_PL`.
- [ ] Polish diacritics render with no missing glyphs on the target Android UI.
- [ ] Card body, option, reaction, HUD, tutorial, and minigame screens pass a
      portrait-layout localization check.
- [ ] Every literal quote in locale content maps to one registry ID whose exact
      text matches and whose status is `cleared` + `allowed` for `in_game_text`.
- [ ] Candidate/blocked quotes cannot enter a release locale payload.
- [ ] In-game quote clearance does not unlock store or marketing use.
- [ ] If a quote is unavailable, its ordinary fallback copy preserves the same
      `card_id`, `option_id`, and mechanical outcome.

## Out of Scope

- Choosing additional languages.
- Changing card design, rewards, balance, progression, or minigame rules.
- Recording voice-over.
- Granting or interpreting legal permission.
- Writing Google Play marketing copy from an in-game-only quote clearance.
